# Native facade Windows checks

This is an STA .NET 10/WPF executable that references the genuine `modern/Main/PCL-Living-Fork.Modern.csproj`. It adapts LF's `Test-MapDetails.ps1`, `Test-ResourceEntryPoints.ps1`, and `Test-WorldDetails.ps1` to the actual C# Main models and original-name page adapters. It does not contain a second filter, world reader, settings engine, or Main substitute.

Build the real launcher first, then build this project with `-warnaserror -p:BuildProjectReferences=false` so its own warnings fail without rebuilding Main's separately recorded warning baseline. The normal project reference remains active. The local-only `LauncherMainAssembly` override can reference an already-produced complete genuine Main directory for isolated compile checks; CI uses the project reference.

Run `PCLLF.Native.Facade.Tests.exe` on Windows to select all nine default groups, or pass `--groups map-details,resource-entry,world-details,registry-names,theme,file-tasks,updater`. Empty or unknown groups fail. A group is printed as `PASS native facade <name>` only after its assertions complete; unselected groups are not counted. The parent process copies the complete genuine launcher/host runtime output into a unique temporary GUID directory, starts its Windows apphost there with a 60 second deadline, then removes that directory. Non-Windows execution fails.

- `map-details`: the original map/zero/resource-pack filtering assertions run through the genuine Main detail page adapter, real loader output, and Core controller. Live model references and the controller's single state are checked. The page is deliberately uninitialized, as in the original script; this is not UI construction acceptance.
- `resource-entry`: the actual Main queued single-button message normalizes null captions; original instance/download/dependency routes survive. New LF's exact six-element arguments preserve a matching instance, carry it through dependency navigation, and drop it after a version change. Actual folder selection honors explicit target, selected instance, deliberate cache, and shared/isolated paths read from real fixture INI files.
- `world-details`: actual Main `WorldMetadata` reads synthetic gzip/NBT data. It checks the complete original field/caption contract, basic/detail distinction, legacy absent values, corrupt/missing files, file-link rejection, unchanged bytes, and released/exclusive/read-only/game-writer handles. Link creation is required and is not silently skipped.
- `registry-names`: genuine Main `Settings.RegistryValueName`/`IsMicrosoftAccountSetting` map all 13 Microsoft account/cache names to `_LF`; unrelated synthetic names remain unchanged. No account contents are used. `HasSaved` and registry snapshot APIs must never be called by this host because they do actual IO.
- `theme`: the separately frozen U001 sample exercises actual production theme/palette/bitmap/tooltip-card code with synthetic single color slots. It opens one offscreen Window, performs real worker-to-UI dispatcher refresh, loaded/unloaded/reloaded subscriptions, mutable/frozen brush behavior, dark/default backgrounds, panel clamps, tooltip child replacement, and failure/finally cleanup. It restores resources and closes the Window. This proves the production rule with the fixture host; it does not claim that Main's live `ModSecret` color fields were exercised.

## Isolation and identity

Before constructing the actual private `PCL.Application`, the fixture replaces only existing mutable platform delegates on its real Identity/Settings hosts. Hardware/seed reads return explicit synthetic values. Seed persistence, physical-memory fallback, and registry read/write/has/open/candidate enumeration count and throw. Even a production-caught forbidden access fails the fixture. Actual INI delegates still run, restricted to the GUID directory and its relative `Setup` file. Settings cache and delegates are restored in `finally`; no product field or fake secret/identity service is added.

The genuine App constructor and BAML `InitializeComponent` run through the generated `/LivingPCL;component/application.xaml` URI. WPF's process-static `Application.ResourceAssembly` naturally remains the test-host entry assembly: its setter requires a null `EntryAssembly`, so this executable must neither set nor restore it. The fixture verifies that the qualified BAML bytes equal Main's own embedded `application.baml` and that the real App loaded Main's role brush and implicit control style. LF Startup/SessionEnding/UnhandledException handlers and framework StartupUri are removed before any dispatcher pump. No `Application.Run`, MainWindow, account migration, updater startup, network request, audio device or real hardware query is invoked. The four data groups do not show a Window or pump the dispatcher. The theme group and file-task callback drain pump only after those LF startup hooks are detached.
