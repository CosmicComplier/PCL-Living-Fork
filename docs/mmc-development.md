# MMC 兼容开发记录

设计依据为 [R7 map](mmc-instance-design.md)。开发从 `e5c2bef`
（已确认设计的共同基线）开始，集成分支为 `codex/mmc-compatibility`。
这里只记录功能开发与验证，不是版本更新说明。

## 第一批子分支

| 子分支 | 负责范围 | 接入限制 |
| --- | --- | --- |
| `codex/mmc-core-parsing` | P0 小型纯边界实验；通过后实现单个 MPL-2.0 Core、来源包解析、自有规则用例 | 不访问磁盘/网络/宿主类型，不生成可直接执行的启动配置 |
| `codex/mmc-host-foundation` | 只读管理记录识别、损坏记录阻断、实例/游戏/本地库根验证 | 不接通旧扫描、安装、设置写入、启动或修复 |
| `codex/mmc-sample-baseline` | 本地 ZIP 审计、真实 GTNH 输入摘要、自有合成 ZIP 回归 | 原包只读；条目审计不等同于兼容或游戏验收 |
| 集成分支 | 真 Core 项目引用、两个 solution、测试分组/选择器、真实 Main 依赖检查与来源记录 | 宿主保留现行许可；本地集成，不合并 main 或发布 |

各 agent 使用独立 worktree，只提交其负责文件。集成时读取差异、应用本地提交，
然后使用真实项目引用重新验证，不能以各自临时测试代替集成结果。

## 独立复核中的修正

本次 Astra high 对 P0/P1 切片进行只读复核；与 R7 之前的设计审查分开记录。
已经落实的修正包括：

- 源包的纯目录大小写别名保留，文件冲突仍拒绝；审计路径查找统一使用其显式受限比较配置。
- 路径长度、深度、累计原始名称和隐式前缀预算在分配前校验，补充 Windows 特殊设备名。
- Core 将字面空 `equals`/`suggests` 视为未声明，同时保留原字段；不把空串误判为精确版本。
- 定义/提示丢失但仍有 LF 源、覆盖、制品或运行缓存的实例，继续保留管理证据并阻止普通后端回退。
- 审计输出拒绝覆盖已有文件、原包及其链接；新文件独占创建，原包只读。

中央目录在创建 ZipFile 对象前的预算预检、直接补丁位置/UID 与保留路径对齐
已由 `033dd58` 集成并通过关闭复核。两原包的中央目录分别为
3,106,576 / 3,107,461 字节；候选路径前缀约9.73Mi字符，均低于本批默认预算。
最终只读原包报告、Core 现场解析、各项构建与测试日志均在集成工作树
`artifacts/mmc-integration/`，目录不纳入源码提交。
