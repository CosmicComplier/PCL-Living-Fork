# MMC 版本 JSON 外部改动处理

生成的 `<实例名>.json` 不是作者补丁来源。文件存在但 SHA256 不等于保存的投影摘要时，
普通补全不会静默覆盖，也不会把当前 JSON 接纳为作者声明。

概览页点击“补全文件”后，如果主定义、配置及版本 JSON 的管理提示仍能证明同一实例／代数，
程序会先显示保存的入口、参数、库清单与当前 JSON，再要求明确选择“保留副本并重建”。
对话框期间不持有实例准入或设置静默化；未确认不发布任务。

确认后，当前 JSON 的精确字节以内容摘要命名，保存在
`PCL/MmcProjectionBackups/<SHA256>.json`。副本与从原定义重新生成的 JSON、
新代数的主定义及设置投影一起进入同一个 MMC 文件事务。
副本属于私有恢复证据，不是组件元数据、启动输入或公开整合包导出内容。

准备和提交时重新核对固定实例 ID、代数、主定义摘要、当前 JSON 摘要及实际合并的配置提示。
确认后源文件继续变化、目标副本已有未知字节、配置属于其他身份、活动／未知会话或待恢复事务时停止，
保留原现场。管理提示损坏或相互冲突时，不提供这种自动重建；需要先明确恢复身份。

只缺少生成 JSON 的情况继续使用既有安全补全，不要求外部变化确认；普通 PCL 版本保留原修复流程。

## 验证

根 Main 编译保持既有 78 警告／0 错误，Native 构建 0 警告／0 错误。
`mmc-projection-rebuild` 实际走 Controller、检查确认、真实修复任务和文件事务，
验证副本逐字节保留、作者入口／JVM 恢复、ID 不变、代数递增与玩家文件保持。
`mmc-projection-admission` 验证过期文件、未知副本和异身份提示拒绝；
既有 `mmc-repair-admission` 再次通过。
`mmc-projection-cancel` 另外验证拒绝确认时不创建修复任务、决定前取消时当前 JSON／主定义保持且副本不发布，
决定后取消仍完整保留副本与成功重建结果；原 60 秒预算和真实任务收尾保持。
这些是自有小包的实际程序接线证据，没有执行游戏或操作用户桌面。
