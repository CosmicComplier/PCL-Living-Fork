# 当前持续目标：完成现有 LF 的 C# 与现代 .NET 迁移

当前目标是将 PCLLF 已有产品实现迁移到 C#、.NET 10 和 WPF，完成功能等价、数据兼容、资源依赖、发布产物及旧版更新桥的验证。做到本目标的全部验收项后停止自动续跑。本目标不自动转入新增 MMC 兼容或性能阶段。

当前状态：`in_progress`。正式modern/Main完整C#/.NET10 WPF与LF50主要功能已接，真实Windows Debug/Release构建、54资源getter、原生四角色包、C#凭据和可选联机编译通过。最新f68321a的Native两配置24/25族、Release真实Registry、225/226/228启动合同及两轮正常冷启/关闭/复开通过；整合包更新完整测试族已通过，MMC精确命令及旧版桥成功退出仍未验收。原44消费者、现代UI/动画与双平台严格比较已有实际成功记录。默认C#发布入口切换、旧VB比较树实体退役、真实账号/游戏与主要交互最终验收继续推进；新增MMC/性能/Rust/C++仍延后。

完整工程背景见 [MIGRATION.md](MIGRATION.md)。可执行任务、进度、验证证据和下次入口只维护在 [MIGRATION_STATUS.md](MIGRATION_STATUS.md)，续跑时从账本继续，不重新建立同一套计划。

## 明确延后

以下任务保持 `deferred`，不因当前批次完成或调度触发而自动开始：

- 新增 MMC／Prism 组件、补丁、库合并、Java 交集、LWJGL 或 GTNH 专用规则与样本验收。
- 缓存、扫描、后台任务、内存、启动速度和文件处理的性能优化。现有必要的基线测量和回归可记录，性能提升不是本目标的交付项。
- 引入新的 Rust／C++ 原生模块，或以原生化替代尚未完成的 C# 等价迁移。

将来启动这些阶段时另立目标和验收，不扩大本目标的完成条件。

## 执行路线与交付节奏

以“完整功能链迁移并通过LF兼容验收”为一轮交付。每轮围绕一个用户可实际操作的闭环，明确原入口、必要依赖、业务处理、存储／平台适配、界面反馈及验收；同类源码成批转换，再集中解决编译错误、接线和行为差异。内部可以小提交，但不能持续以单个方法、格式规则或孤立接口提取作为主要交付。

恢复后复用现有模块图、固定源码清单与已验结果，只补当前功能链缺口，一次性整理本轮范围和依赖。优先处理阻挡整链的实际控件／呈现宿主／工程前置，尽早形成能承载真实功能的C#／.NET 10 WPF工程；不等全部叶子规则迁完才验证现代工程，也不把空工程、未编译页面或仅核心转换算成整条功能链完成。原任务编号与历史证据保留，按整链需要修订依赖且保持无环；C007d2等子任务作为链内步骤，不机械逐个推进而长期绕开界面／宿主阻塞。

每轮先核对LF相对PCL的差异，再查看固定CE参考中对应的现成C#实现、组件和迁移经验。适合者优先选择性复用或适配，以减少重复转换；逐批记录固定提交、路径、许可、LF特有逻辑与适配理由，仍以LF源码、数据和产品行为为准。不能将CE换作工程底座，也不能因为复用而覆盖LF增改或丢失功能。

兼容检查与生产迁移同步推进：为当前链维护LF基线与迁移实现的行为／数据矩阵，覆盖正常流程、异常、取消／回滚、文件锁、线程／界面交接及相关旧数据和升级入口。影响当前生产行为的差异须修复并通过对应真实Windows检查后才能验收；未验证范围明确保留，不以降低断言、删除旧样本或扩大捕获取得通过。研究和兼容适配围绕已确认差异与当前链所需边界展开，沿用已有适配和证据，避免重复扫描或无范围地扩展单个BCL细节；不影响当前链的事项记录到对应后继任务。

允许子代理按互不冲突的文件／任务协作，研究、生产实现与测试可以分工；主执行者统一集成、自审与提交，不同时切换共享分支或改写同一文件。用户随后要求尽量提高迁移速度，当前环境最多7个并发执行者（主执行者＋6子代理）；按用户最新要求，6个子代理均优先负责有独立文件边界的大模块生产迁移，主执行者承担集成、审查和必要测试；某批生产完成后可再分配其验证工作。跨模块合同先冻结，完整稿统一接入；共享Core／固定输出的构建由主执行者协调，不以并发覆盖未知改动或重复跑全量。基础设施和研究有明确出口，只交付当前链需要的最小前置；恢复后的G005限于现有测试分组、选择和CI路由，不另建大型框架。

以实际可运行且兼容验收通过的功能链汇报成果，同时标明已迁／未迁入口和剩余阻塞。基线、研究、测试、文档和前置单独记账，不据提交数、方法数、测试数或C#增量声称整体完成率。进度和证据在账本原条目集中更新；保持必要追踪与详细提交正文，减少重复说明、重复规划和仅为汇报而产生的零碎提交。

## 测试选择与兼容门禁

日常小改默认运行受影响模块的真实生产代码测试及兼容样本；共享依赖变化补受影响下游；整链交付运行该链集成／Windows回归。跨链影响广或范围无法可靠确定的框架／公共契约变更，以及发布前，才升级为全量产品回归。纯文档变更不重新构建或运行产品测试；检查已通过后，只因新改动、失败或未解决风险重跑相关检查。

G005为现有入口增加按模块／功能链筛选和变更／依赖路由，明确记录实际运行及未运行范围，不将未选中测试算作通过，也不允许空选择静默成功。保留现有全部兼容样本及必要整链／发布门禁；断言以可观察行为、数据和必要兼容契约为主，避免无关内部实现细节导致大面积测试改写。定向测试的运行隔离与必要依赖构建同时满足，不把少跑测试误写成取消兼容验收。

## 任务与提交策略

每个任务保留唯一编号、依赖、生产入口、改动边界、实际验收、状态和下一步。在本轮选定的完整功能链内按真实依赖推进，先收尾已开始且相关的批次；发现阻塞时先修订必要前置并继续可独立集成的链内工作。已有小任务无需逐个重新建立计划；任务表与新路线不一致时，恢复后只调整当前交付涉及的编号、依赖和范围，并记录原因，不重新扫描整个仓库。

依赖清楚、范围小且相关检查通过的批次可直接commit／push迁移分支；跨模块、高风险或较大批次按需提交以迁移分支为base的PR，自审与必要检查通过后合入。不得向main提交或合并，不得force push，不得将未验证写为通过。内部小提交用于可审查和故障定位，整链交付仍须满足上述双重验收。

commit 与 PR 使用明确标题和详细正文，尽量覆盖该批次实际修改。正文说明问题与目的、涉及的生产代码／配置／文档、关键行为和兼容边界、参考的 LF／CE／上游固定来源、实际验证命令与结果、未验证部分和后续事项。PR 描述面向未读聊天的审查者，说明最终实现和自审结论；范围变化时更新标题和正文。多行正文用 UTF-8 文件或结构化参数提交，保留真实换行。

续跑调度按小时触发。首次初始化和已有活动批次应避免重叠；每次以远端迁移分支及本账本作为续接依据。

每次续跑遵循以下顺序：

1. 读取本目标、状态账本、模块映射和适用的 `AGENTS.md`；确认分支，记录 `git status`、当前提交和未完成批次。
2. 识别未知本地改动及其归属。保留已有变更；不以 reset、clean、自动 stash 或覆盖文件消除冲突。只阻塞与未知变更重叠的操作，独立工作可继续。
3. 按账本选择本轮完整功能链，复用固定CE参考并批量推进相关源码及必要工程／宿主前置；在该链内先收尾已开始且依赖满足的任务，只为实际变化修订相关计划。
4. 按生产功能链实现、自审并运行适当检查。Windows、GUI、账号、网络或发布检查没有实际环境时，分别记录未运行原因及后续动作。
5. 根据风险选择直接提交或以迁移分支为base的PR，推送远端检查点。集中将实际生产改动、接通入口、选择的测试／结果、CI链接、兼容限制和下一步写回原账本条目，避免续跑重复劳动与重复说明。
6. 所有验收完成后将目标标记 `completed`，暂停对应续跑调度；调度管理入口暂不可用时记录待暂停动作，并停止继续选取新任务。

临时构建产物、SDK、测试账号资料、访问凭据和机器私有路径不得作为迁移证据提交。并行协作按文件和任务分配所有权，集成者统一检查差异与提交，子代理不覆盖其他批次。

## 最终验收

- 提交树清单中 LF 产品 VB 源文件为零。原有可选功能与生成源码均已转换，或在不降低约定能力的前提下以明确记录的等价方式替换；不通过隐藏、改扩展名或排除编译来减少数量。
- 主程序与 LF 自有依赖完成 .NET 10／WPF 的 Windows Debug、Release 构建、发布产物启动和实际运行验证；第三方及子模块框架兼容已有记录。
- 初始 LF 的回归脚本已适配新实现并实际执行。迁移新增测试通过真实生产入口运行；共享业务规则的无 WPF 测试只作为对应范围的证据。
- 账号、`Setup.ini`、版本隔离、游戏目录、用户修改、备份、还原点和更新通道使用旧数据样本完成对照；不将构造对象或纯源码断言当成完整账号或 GUI 验收。
- 按钮、滚动、页面加载、动画中断和叠加、窗口唤醒、单实例等 WPF 行为完成新旧对照。
- 安装、更新、备份、恢复等文件操作在取消或失败后等待负载、提交或回滚实际收尾，再释放版本占用；故障和恢复样本通过。
- 旧版更新桥、产物命名、凭据保护、资源解析和既有 MMC 等整合包能力保持等价；来源许可、模块清单、任务账本和最终证据同步完整。

初始 Windows 构建通过不等于新迁移批次通过；Linux 纯 C# 测试通过不等于 WPF 或完整启动链通过。任何未完成的必要验收均保持显式阻塞，目标不能提前标记完成。
